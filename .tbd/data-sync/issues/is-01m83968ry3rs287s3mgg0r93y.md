## Goal

The Files tab's File type chooser (multi-select, "Any type" by default, with Groups and
Families presets and per-type counts) appears at the top of every multi-file diff and
narrows the diff to the changed files of the chosen types. Reading only a change set's
documents, or only its Python, should take one choice.

## Where it lives

Every multi-file diff mounts through `mountDiffView` in
`builtin_plugins/diff/diff-view.js`, whose `.diff-toolbar` already holds the Unified/Split
control (`renderLayoutControl`). That covers a direct comparison, a commit's page
(`summaryHost`), and a pull request's Files tab (`summary: false`). The chooser goes in
that toolbar, before the layout control, for diffs of more than one file only.

Both comparison routes resolve through one function: `/api/plugin/github/pull-comparison`
delegates to `comparison_at` in `builtin_plugins/diff/sidekick.py`, beside
`_narrow_to_path`, which already narrows a document and keeps it a valid file-diff-v1
document. So one narrowing serves every diff source.

## Design decisions (recommended; confirm before T5)

1. **Membership is route-owned** (AGENTS.md, CLI and Functional UI Parity). `types=` on
   the comparison routes narrows the manifest on the server; the browser asks again
   instead of filtering a held manifest with a second matcher. A truncated list is
   then narrowed over the files the server has, not only the first page the browser
   holds.
2. **One matcher.** The server's `_matches_types` (`git/content_routes.py`), which already
   matches "like the SPA type filter", moves to a shared module both the Files tree and
   the diff narrowing call.
3. **A change matches on either side.** A rename from `.txt` to `.md` is shown under
   both types, since the reader asked about files of that type and this one is one on
   one side.
4. **Counts come from a route too**, in the `/api/rollup` tally shape (extensions,
   canonical_extensions, type_families, type_presets), over the whole change set, so
   the menu lists only types present with their counts. File Diff Format v1 gains no
   undeclared property.
5. **The selection is held per page, never persisted.** A pull request's tabs share it;
   a new page starts at Any type. A remembered filter would silently hide files in the
   next review.
6. **The Diff summary keeps describing the whole change set.** The toolbar says what
   the filter hides ("12 of 35 files") with Clear; a filter that keeps nothing is a
   labeled state with Clear, never an empty diff.

## Children and order

T1 shared matcher → T2 `types=` narrowing route and T3 tally route (parallel) → T4 SDK
menu builders (parallel with T2/T3) → T7 measure switch cost → T5 toolbar chooser →
