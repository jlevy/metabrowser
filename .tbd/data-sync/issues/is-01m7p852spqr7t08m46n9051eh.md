PR #529 (review A, L4) shows a Pulls row's or stack heading's file statuses whole or not at all with a wrapping row-reverse flex line whose status group is flex: none, flex-wrap: wrap, so its min-content floor is its longest word (src/metabrowser/builtin_plugins/github/styles.css, .github-pulls-change-line > .change-line and .github-pulls-stack-change > .change-line). Chrome 152 takes that plain min-content as the item's contribution; CSS Flexbox 9.9.3 would clamp a non-shrinkable item to its flex base size, which would make the floor the whole status run, so in WebKit (the macOS app's WKWebView) a narrow line could drop entirely instead of showing its totals alone. Measure the row and stack-heading sweeps (tests/dom/github-pulls-row-lines-chrome.mjs, github-pulls-stack-lines-chrome.mjs) in WebKit, e.g. through apps/macos/webkit-gate, and if WebKit differs, give the line a floor both engines agree on. Done: WebKit measured at the sweep widths, recorded beside the CSS, and either matching Chrome or fixed.
