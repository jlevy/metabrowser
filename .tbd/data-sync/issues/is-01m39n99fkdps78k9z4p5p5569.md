Found in the step 7+8 security review (2026-09-24): one file whose name contains a backslash, in a served folder (trusted or --untrusted), makes the inventory walker raise ValueError 'dirty path must be a canonical POSIX-relative path' (inventory_engine/contract.py:187). /api/index/progress then reports failed and /api/tree returns 500. The same name served from a Git pin works. Check whether it predates v0.12; handle such names like other unusual names (list them, with safe display) or skip them with a typed diagnostic rather than failing the whole index. Add a test.
