run_git logs 'git <args> exited <rc>: <stderr>' at INFO for every non-zero exit, but most non-zero exits are deliberate probes:

- Serving any non-git directory prints 'git rev-parse --show-toplevel exited 128: fatal: not a git repository' every GIT_REPO_INFO_TTL_S (5 s) for as long as a browser is open.
- Opening the Git tab prints one line per unresolved candidate ref from resolve_default_scope ('rev-parse --verify --quiet <ref>^{commit} exited 1:' with empty stderr).
- repo._resolve_head probes detached/unborn HEAD the same way.

A non-zero exit is a return value the caller classifies, not an event the process layer can rank. Demote to DEBUG and keep genuine failures visible at the route boundary, which already logs WARNING - but make those warnings carry git's stderr, which str(GitCommandError) deliberately omits.
