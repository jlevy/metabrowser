- The recent folders the macOS app shows, and `metab --recent`, now hold only what you
  opened. The app records each folder or repository once, as it opens it, and a `metab`
  serve records only when you run it at a terminal.
  A `metab` that an agent, a test, a script, or a tool runs has no terminal, so its
  folders no longer push yours out of the 16 the menus show.
  Choosing an open folder in the folder chooser or Switch Folder… now moves it to the
  top as well, and an open is listed even when its server then fails.
  `METABROWSER_RECORD_RECENT=0` still turns recording off, and `--recent-add` still
  records unless it is `0`. A script that should record what it serves sets the variable
  to `1` ([Recent Targets](docs/command-line.md#recent-targets)).

- **App contract:** the macOS app starts every server with `METABROWSER_RECORD_RECENT=0`
  and records each open itself with `metab ROOT --recent-add`, a folder named by a path
  that ends in a slash.
  A serve whose stdin is not a terminal, as every server the app starts is, no longer
  records unless told to with `1`, so an older app with this `metab` lists only the
  folders it opens while they are already open, until the app is updated with it.
