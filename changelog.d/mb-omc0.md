- **A pull request’s status speaks one visual vocabulary.** Merge conflicts are orange,
  a tone of their own (Primer’s severe), so they never read as failing checks, which
  stay red, and they take a glyph of their own, a conflicted branch, in place of the
  warning triangle. The pull request page’s status chips now lead with the glyph the
  Pulls tab, the stack menu, and the stack page draw alone for the same meaning: the
  header’s readiness chip, each Merge status row, and each check in the Checks tab,
  whose marks are all circles, as GitHub draws a check run’s. Ready to merge is a double
  check, a rule’s block a shield, and leaving the merge queue a list with a cross.
  `metab` reports each Merge status requirement’s tone beside its status.
  See
  [Pull Request Status Vocabulary](docs/design-system.md#pull-request-status-vocabulary),
  which sets each mark beside the one GitHub draws.
