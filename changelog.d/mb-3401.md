- A Git revision’s files and folders now show their age, the time of the last commit
  that changed them, as a hosting site’s file list does, on a mirror, a pull request’s
  head, and a branch or tag of a checkout alike.
  Git reads it (`git last-modified`, Git 2.53 or newer) in the background, so a page
  opens at once and the times arrive a moment later, and the answer is kept per commit,
  so coming back to a branch is free and a branch whose ancestor is known reads only the
  commits since it. A shallow clone says a file is older than its oldest commit and never
  dates it by that commit.
  With an older Git a revision shows no ages, as before, and `metab --doctor` reports
  the Git it found and the release it needs, and in the app’s Check Setup…. Adds the
  `file_ages` block of a pin’s `/api/capabilities`, an `ages` state on its `/api/tree`
  and `/api/index/progress`, and an `mtime` on tree nodes.
