- Each `gh` call’s record in the event log now says which lane its work served: a page
  on screen or a reader’s own action (`visible`), what the session reads for that page
  without showing it, the attended pull request and the list behind a pull request page
  (`attended`), the prefetch (`prefetch`), or the catalog’s scan when it is due by age,
  its backfill, the scan of every open pull request’s status, and the cores walk
  (`background`). `GET /api/plugin/github/gh-requests` adds up the calls for each lane
  as well, and no longer lists the lane among what the log does not hold
  ([The Request Report](docs/project/architecture/arch-github-pull-requests.md#the-request-report)).

- `POST /api/plugin/github/pulls-refresh` takes an optional `"lane"`, `"visible"` (the
  Pulls tab’s ask, and the default) or `"attended"` (a pull request page’s ask for the
  list behind it), which the probe, the catalog’s pages, and the scan it starts record.
