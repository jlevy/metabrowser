# Parity Registry

**Status:** Enforced.
`devtools/check_parity.py` reads both tables below in `make lint` and `make lint-check`,
and `tests/test_check_parity.py` and `tests/test_parity_runtime.py` check the checker.

The two tables that bind Metabrowser’s surfaces to command-line evidence: one row per
registered route, and one per user-visible functional aspect.
The rule they enforce is in
[AGENTS.md](../../../AGENTS.md#cli-and-functional-ui-parity), the reasoning behind it in
[Development](../../development.md#cli-and-functional-ui-parity), and the routes
themselves in [Views, Models, and Routes](arch-views-models-routes.md).

## Routes

A row’s status is `covered`, naming goldens in `tests/golden/` that each run the route
through the CLI mode the row names, at least one of them exiting 0, or `exempt`, giving
the reason the route has no model a transcript can pin.
`check_parity.py` fails on a registered route with no row, a row for a route that is not
registered, any other status, and a golden that never runs the route.

## User-Visible Functional Aspects

A row’s tier is `data`, a route that `metab` reaches and a golden pins; `interaction`, a
browser-owned state machine whose `node tests/dom/<session>.js` session runs the named
production functions; or `paint-exempt`, browser-only layout or platform behavior with
its reason and focused test evidence.
**Data inputs** is `owned-route` for a data row, `local-only` for a paint row, and for
an interaction row the covered routes it reads, `local-only`, or
`transport-exempt:/api/events`. `check_parity.py` runs each interaction session and
fails when a named function did not execute.
